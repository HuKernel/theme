02 / 环境切换

三个环境，一枚快捷键

变量在本地解析，令牌存进系统钥匙串。切换环境只改写请求地址与变量注入，不触碰请求历史与断言。

变量当前解析值说明
baseUrlhttps://api.mercury-staging.dev/v2服务地址
apiKeysk_staging_9f3a****存于系统钥匙串
regioncn-east-1资源区域
timeout30000单位 毫秒

机密不出本机

apiKey 与 OAuth 刷新令牌写入 macOS 钥匙串、Windows 凭据管理器。导出集合时自动脱敏为 sk_live_****。

03 / 核心能力

为高频调试而生的工具箱

每一项能力都对应一个真实的高频动作：导入、切换、对比、回归。没有仪表盘，没有社交动态。

请求构建器

14 种 HTTP 方法，cURL 一键导入，请求体按 JSON Schema 实时校验。光标停在哪个字段，校验提示就跟到哪里，不用点开第三层面板。

curl -X POST https://api.mercury.dev/v2/checkout/sessions -d @body.json CtrlI 导入 cURL

环境与机密

变量解析全部本地完成，令牌写入系统钥匙串，集合导出自动脱敏。

CtrlE 切换环境

团队集合

集合即 Git 仓库：分支、评审、回滚，与代码同一节奏演进。

main / feat-sms-login

断言与测试

把断言写进请求本身，CLI 一条命令把整个集合跑进 CI。

portman run checkout.yaml

响应对比

双击任意两次响应生成字段级 diff，接口回归一眼可见。

CtrlD 对比上次响应

05 / 文档与快捷键

三步跑起来

从安装到跑进 CI 不超过五分钟。命令行与桌面客户端共享同一份配置，改一处即生效。

01

安装客户端

brew install --cask portman 或 npm i -g portman-cli，两者可并存。

02

打开工作区

portman open checkout-team，团队集合按 Git 拉取，环境变量占位自动就位。

03

发送第一个请求

填好地址按 CtrlEnter。断言与请求一起保存进集合，下一人在同一路径上继续。

$ portman login
$ portman sync checkout-team
  已同步 4 个集合 / 175 个请求
$ portman run collections/checkout.yaml --env staging
