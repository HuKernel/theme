流向桑基，把每一吨都记在账上

Best chart type: Sankey Diagram / secondary: Alluvial, Chord Diagram

桑基图回答一个漏斗答不了的问题：东西从哪来、到哪去、路上分了几岔。 下面以一座城市一天 2,450 吨生活垃圾的真实感数据，画一张三段全量桑基： 来源四类，处理四类，去向五类，25 条流量带全部手写贝塞尔曲线， 带宽与吨数严格成正比（40 像素标尺 = 200 吨/日），逐路进出守恒。

数据形态 Flow / Process 首选 Sankey 备选 Alluvial / Chord 流量 25 条（少于 50，SVG 阈值内） 交互 Hover + Drilldown 无障碍风险 conditional

官方规范档案

No.12 / Flow / Process Data
何时用
量在节点之间的流转与再分配；多源多汇的分布结构。
何时不用
流向成环（改用网络图）；流量对少于 3 对；移动优先场景。
数据量阈值
流量少于 50 用 SVG，达到 50 用 Canvas，超过 200 把小流量归并进其他节点。本图 25 条，手写 SVG。
颜色规范
从源色到目标色渐变；流量带透明度 0.4 到 0.6（本图 0.5）；节点标签始终可见。
不靠颜色
辅以线型区分：虚线边框标记损耗去向（烟气与蒸发）；数值全部直标。
无障碍
风险等级 conditional；后备为流量表加摘要；键盘 focus 读值 / Enter 下钻 / 返回键回退。
备选图形
Alluvial 冲积图 / Chord 弦图。
推荐实现
D3.js（d3-sankey）/ Plotly；交互层级 Hover + Drilldown。

取舍与后备 / 桑基与漏斗怎么选

桑基与漏斗的取舍

同一笔账，两种图形各管一段
维度 漏斗 桑基
数据形状单一线性路径，逐级递减多源多汇，任意分配
岔路与合并表达不了岔路，只能记为流失任意分叉合并，但不得成环
守恒视角只盯逐级转化率逐路守恒，损耗也入账（本图烟气与蒸发 710 吨即明证）
数据门槛三到七级为宜少于 3 对流量不必上桑基；超过 200 对先归并
触屏与窄屏天然窄长，适合移动端官方明示移动优先场景不建议，窄屏给表格后备

判断口诀：一条路走到底画漏斗，多岔口分账画桑基，环形流转直接换网络图。

与图鉴第 07 号（转化漏斗）互为镜像：那一页漏斗当主角、桑基只做渠道分流的迷你样；本页桑基当主角，三段全量、逐路守恒，漏斗退为取舍参照。行为桑基的另一个实例见 用户行为分析。
